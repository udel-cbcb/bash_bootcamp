# Tips for Troubleshooting

Here are a few tips and tricks to keep in mind whenever you are troubleshooting an issue on the command line.

- The computer is (almost) always right
    - The hardest thing to accept at the beginning of your computational journey is that if something isn't working, it's probably because you made a mistake.  Don't let that bother you; data scientists of all experience levels encounter issues all the time!
- If you get an error, read it carefully
    - Good error messages are useful.  Take the time to try to understand what the error is telling you.  Look up any words you don't understand to help you interpret the message.
- Carefully inspect your code
    - Make sure to check every character, down to the spaces.
- Not every issue results in an error message
    - If you get no error message, but a command still does not result in the expected output, you still have an issue.  In this case, carefully examine your command.
- Keep the manual handy
    - Just like for bash, manuals and other documentation exist for any good software or programming language.  Use these to look up details of how a command/line of code can be used and refer to any included examples for extra tips.
- Google is your best friend!
    -Google is your greatest resource when troubleshooting errors.  Often, just copying and pasting your error into the search bar will result in the exact answer you've been looking for.
- LLMs are incredibly useful, but can be fickle
    - Large Language Models (like ChatGPT or Claude) are great for quickly diagnosing command-line errors, explaining cryptic syntax, or generating bash one-liners. However, while they can save you time, they can also hallucinate incorrect flags or produce outdated commands. Always double-check generated code before executing it in your terminal, especially if it involves destructive operations like `rm` or permissions changes like `chmod`.
